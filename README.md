# Miacis 館内サイネージ

韮崎市の中高生の居場所「青少年育成プラザ Miacis」の館内モニター用サイネージシステムです。

- **表示ページ (`web/index.html`)**: 館内のモニターにつないだタブレットPCで全画面表示し、今日が掲載期間内のスライド（画像・動画）を自動でループ再生します。
- **管理ページ (`web/admin.html`)**: スタッフがスマホやPCから画像・動画を開始日・終了日（日付単位）付きでアップロード・編集・削除できます。流す順番は日付順（開始日の早いもの → 同じなら先に載せたもの）で決まり、並べ替えはありません。

## 1. 本人が行う公開手順

### ステップ 1: Supabase のマイグレーション適用
いまは英単語バトルの Supabase（`aljlbxvucscmpbcuccin`）に同居させています（2026-09-28 本人決定）。

- **Mac のターミナルで `bash tools/apply-remote.sh` を実行します**（Supabase CLI にログイン済みであること）。
  前後で英単語バトル側の権限の指紋を比べ、変わっていないことを確かめてから「完了」と出ます。何度実行してもかまいません。
- `supabase db push` は使わないでください。英単語バトルの migration 履歴とぶつかります。
- 別のプロジェクトに置く場合は、SQL Editor に `supabase/migrations/0001_signage.sql` を貼って「RUN」を実行してもかまいません。
   - `signage_members`, `signage_slides` テーブル、RLS ポリシー、ストレージバケット `signage` が作成されます。

### ステップ 2: ユーザー登録の制限（セキュリティ設定）
**どの Supabase に置いたかで、やることが違います。**

- **サイネージ専用のプロジェクトの場合**: 「Authentication」>「Providers」>「Email」で
  **「Allow new users to sign up」をオフ**にします。外の人が勝手にアカウントを作れなくなります。
- **英単語バトルと同じプロジェクトに同居させた場合: ここは触らないでください。**
  英単語バトルは中高生の登録にこの機能（`auth.signUp`）を使っているので、オフにすると誰も登録できなくなります。
  サイネージは `signage_members` に載っている人しか読み書きできない作りなので、登録が開いていても中身は見られません
  （`tests/db/signage.test.mjs` の「members に載っていない authenticated ユーザーは…」で確かめています）。

### ステップ 3: 鍵つき URL を作り、共用アカウントを作る（**GitHub に公開する前に**）
スタッフは**合言葉を入れません**。鍵を埋め込んだ URL（`admin.html#k=…`）を開くだけで入れます。
館のタブレットも、キオスクの起動 URL（`index.html#k=…`）に鍵を入れておけば、電源を入れるだけで流れ始めます。
`#` より後ろはブラウザがサーバーへ送らないので、GitHub にも Supabase の記録にも残りません。

1. Mac で `node tools/make-links.mjs` を実行する。ランダムな鍵2つと、配る URL 2つが出る（どこにも保存されない。出た画面を閉じる前に次をやる）
2. Supabase Dashboard →「Authentication」→「Users」→「Add user」→「Create new user」で2つ作る（「Auto Confirm User」にチェック）
   - `staff@signage.miacis.example` / パスワード = スタッフ用の鍵
   - `display@signage.miacis.example` / パスワード = 表示端末用の鍵
   - このメールは実在しなくてよい（メールは送らない）
3. スタッフ用 URL をスタッフに渡す（LINE など）。ブックマークかホーム画面に置いてもらう。館のタブレット用 URL はキオスクの起動 URL にする
   - URL を転送された人も使える。漏れたら `node tools/make-links.mjs` で作り直し、Users でパスワードを新しい鍵に変えて `tools/sql/change-passphrase.sql` を流す（古い URL は使えなくなる）
   - URL の鍵が使えないときは、画面に合言葉の欄が出る。鍵をそのまま入れても入れる

### ステップ 4: 共用アカウントに権限を付ける
1. `tools/sql/setup-accounts.sql` を SQL Editor に貼って「RUN」。最後に2行（editor と display）出れば完了です。
   - 作ってから24時間以内のアカウントにだけ権限を付けます（同居先は誰でも新規登録できるので、先に同じメールで登録されていた場合に権限を渡さないため）
2. **URL を作り直すとき**（スタッフが辞めた・漏れた）: Users でパスワードを新しい鍵に変えてから `tools/sql/change-passphrase.sql` を流すと、いまログインしている端末が締め出されます

### ステップ 5: フロントエンドの設定（英単語バトルと同居なら設定済み）
1. `web/js/config.js` を開きます。
2. Supabase Dashboard の「Project Settings」>「API」にある `Project URL` と `anon public key` を転記します:
   ```javascript
   export const SUPABASE_URL = 'https://YOUR_PROJECT_ID.supabase.co';
   export const SUPABASE_ANON_KEY = 'YOUR_ANON_KEY';
   ```

### ステップ 6: GitHub Pages への公開
1. リポジトリの Settings > Pages で、Source を「GitHub Actions」に設定します。
2. `main` ブランチに push すると、`.github/workflows/pages.yml` によって自動的にテストが実行され、`web/` 配下が公開されます。

## 2. タブレットPCでの全画面設定

館内モニター用のタブレットPCで表示ページ（`index.html`）を全画面で開きっぱなしにする設定手順です。

### モニターを縦に置く

館のモニターは縦置きで使います。載せる画像・動画は **縦長 1080×1920（9:16）** で作ると画面いっぱいに出ます（Canva ならカスタムサイズ 1080×1920 px）。横長のものも流せますが、上下が空いて小さく出ます（管理ページで選んだときに知らせます）。

画面を縦にする方法は2つあります。**① を先に試してください。**

1. **端末の OS で画面の向きを変える（おすすめ）**
   - Windows: 設定 → システム → ディスプレイ → 外部モニターを選ぶ → 「画面の向き」を **縦** に
   - Android: 端末によって外部出力の回転に対応していないことがある
   - iPad: 外部モニターへの出力は回せない → ② を使う
2. **表示ページの側で回す（① ができないとき）**
   - 表示ページの URL の後ろに `?rotate=90` を付けて開く（逆さになったら `?rotate=270`）。1回開けば端末が覚えるので、次からは付けなくても回る
   - 元に戻すときは `?rotate=0` で開く
   - ① と ② を両方やると二重に回るので、どちらか片方だけにする

### 端末共通の必須設定
- **画面スリープ・自動オフの無効化**:
  - 設定アプリの「電源とバッテリー」「画面表示」から、画面の自動消灯およびスリープへの移行を **「なし（適用しない）」** に設定してください。
- **電源接続**:
  - 常時給電（ACアダプタ接続）の状態で運用してください。

---

### Windows タブレットPC の場合
Microsoft Edge のキオスクモード機能を使用します。

1. **初回ログイン**:
   - 通常の Edge で表示ページの URL を開き、表示端末用アカウントでログインしておきます（セッションが保持されます）。
2. **キオスク起動ショートカットの作成**:
   - デスクトップで右クリック >「新規作成」>「ショートカット」。
   - 項目の場所に次のように入力します（`<URL>` は表示ページの URL）:
     ```cmd
     msedge --kiosk <URL> --edge-kiosk-type=fullscreen
     ```
   - ショートカットの名前を「Miacisサイネージ」として保存します。
3. **自動起動（スタートアップ）への登録**:
   - `Win + R` キーを押し、`shell:startup` と入力して Enter を押します（スタートアップフォルダが開きます）。
   - 作成したショートカットをこのフォルダに配置します。
   - これにより、端末の電源が入った際に自動で全画面でサイネージが起動します。

---

### iPad の場合
Safari の「ホーム画面に追加」と「アクセスガイド」機能を使用します。

1. **初回ログインとホーム画面追加**:
   - Safari で表示ページの URL を開き、表示端末用アカウントでログインします。
   - 共有ボタン（四角から矢印）をタップし、「ホーム画面に追加」を選択します。
2. **アクセスガイドの設定**:
   - iPad の「設定」>「アクセシビリティ」>「アクセスガイド」をオンにします。
   - 「パスコード設定」でアクセスガイド専用のパスコードを設定します。
3. **固定表示の開始**:
   - ホーム画面に追加したサイネージアイコンをタップして起動します。
   - トップボタン（またはホームボタン）を **トリプルクリック** して「開始」をタップします。
   - これで他アプリへの切り替えやスワイプ操作が無効化され、全画面で固定表示されます。
   - （終了する場合は再度トリプルクリックしてパスコードを入力します）

---

### Android タブレットの場合
Chrome の「アプリの固定」機能を使用します。

1. **初回ログインとホーム画面追加**:
   - Chrome で表示ページの URL を開き、ログインします。
   - 右上のメニュー（︙）から「ホーム画面に追加」を選択します。
2. **画面の固定（アプリのピン留め）設定**:
   - 端末の「設定」>「セキュリティ」>「画面の固定（またはアプリの固定）」をオンにします。
3. **固定表示の開始**:
   - ホーム画面のアイコンからサイネージを開きます。
   - アプリ履歴画面（ナビゲーションのタスクボタンや下からのスワイプ）を開き、アプリのアイコンをタップして「固定」を選択します。

## 3. テストの実行

ローカルでユニットテスト（DB権限テスト・ロジックテスト）を実行するには:

```bash
npm install
npm test
```

ローカルで画面を確認するには:

```bash
npm run serve
```
ブラウザで `http://localhost:3000`（表示画面）または `http://localhost:3000/admin.html`（管理画面）を開きます。
